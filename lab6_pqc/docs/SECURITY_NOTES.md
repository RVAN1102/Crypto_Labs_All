# Security notes

- Cryptographic operations use OpenSSL EVP/provider APIs only.
- Keys are generated by OpenSSL's cryptographic RNG.
- Private keys and shared-secret bytes are never printed or logged.
- Signature and ciphertext files are binary-safe; malformed inputs fail closed.
- ML-KEM uses implicit rejection: a modified ciphertext can produce a
  pseudorandom secret rather than an API error. Tests therefore require the
  derived secret not to match the original.
- Shared-secret buffers are cleansed after use where practical.
- Timing-variance CSVs are educational observations, not a side-channel proof.
- Generated private keys and shared secrets are ignored by Git.
